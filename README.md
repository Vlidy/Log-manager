# Log Management

Лабораторная работа по автоматизации управления лог-файлами.

Работа выполнялась в **Ubuntu через WSL2** в Windows. Для хранения логов используется отдельный раздел, смонтированный в `/LOGS`.

## Основные характеристики

- Обрабатываются логи трёх сервисов: `auth_service`, `data_process_service` и `system_event_handler_service`.
- Проверка заполнения раздела `/LOGS` выполняется с порогом **90%**.
- Для каждой папки сервиса установлен лимит — **1/3 от общего объёма раздела**.
- При превышении лимита подходящие `.log`-файлы архивируются в формат `.tar.gz`.
- Перед удалением исходных файлов проверяется целостность созданного архива.
- Каталог `/LOGS` настроен на автоматическое монтирование при запуске WSL.

## Запуск

Скрипт `log_man.sh` можно запустить вручную командой:

```bash
bash ~/linux-lab/log_man.sh
```

Также настроен автоматический запуск скрипта **каждые 5 минут**.

## Тестирование

Для проверки работы предусмотрен отдельный скрипт `test_log_man.sh`. Он использует временные каталоги и проверяет несколько сценариев: превышение порога заполнения, заполнение ниже порога и ситуацию, когда папка сервиса не превышает установленный лимит.

Запуск тестов:

```bash
bash ~/linux-lab/test_log_man.sh
```

## Файлы проекта

- `log_man.sh` — основной скрипт управления логами и архивации.
- `test_log_man.sh` — скрипт автоматической проверки основных сценариев.
